# Complete narration and shot composition

1. Read the complete narration, script and actual subtitle times first. Derive the film duration from the full supplied speech and subtitle end, never from a demo length or one scene capacity.
2. Map the complete story into semantic sections, then compose multiple shots at actual sentence/phrase boundaries. A topic or section can span several compatible shots.
3. Prefer native groups, implemented basic expressions and legal adjacent groups in this template style. Reuse independently bound instances where appropriate; do not default to mixed styles or a static background.
4. When one group does not fit, re-segment, add or replace compatible same-style shots, use only declared quiet reading holds, and rebind cues. Preserve source-speed actions and continuous output-clock speech, presenter and captions.
5. An out-of-scene cue, protected-action conflict or unmatched candidate rejects the current shot plan only. Retry complete alternative segmentations; never infer a15–19second film limit or default to shortening the user narration.
6. Asset-name conflicts, release-candidate bugs and dependency failures are tool failures. Keep the exact diagnostic and investigate them, rather than calling the script too long.
7. Every candidate must cover the same complete narration. Do not omit sentences or qualifiers, or reduce narrationDuration to hide missing coverage. Verify the first and final sentence, frame count, captions and voice before export.
8. Suggest editorial shortening only when the user explicitly requests it or an actual platform limit requires it; obtain review of the edit. If compatible style coverage is genuinely missing, name the precise gap without promising arbitrary content can always be adapted unchanged.

Example: a32.3second narration with13 subtitle cues need not fit a single15–17second scene. Preserve all13 cues and speech and compose compatible shots from the actual meanings/times. If an11.8second protected action cannot fit a3second ending, choose another ending. This explains planning; it does not invent word times or claim an untested exact result.
