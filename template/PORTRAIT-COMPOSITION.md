# Portrait composition / 竖屏构图修正

新建带人物的B1–B4竖屏默认使用presenter-caption/2，实际渲染人物中心回到
(540,1040)，保留原矩形/圆形、375×509或213×213尺寸和原素材等比裁切。
将B组正文安排在上方，完整字幕沿用short-video的24%底距与右侧16%预留，
逐帧检查完整字形及人物/图文冲突。不靠缩小人像、删除限定词或关闭检查过关。
 B2四项以内保留原正文缩放；五项密集列表独立收紧正文排布，保留全部条目、
 两行内容和原人物尺寸，避免第五卡与人物框、身份标签重叠。
尺寸数字仅是内部实现信息，新布局不向视频观众显示；身份标签仍保留。

portraitComposition=legacy显式保留旧几何。新布局与captionSafeArea=frame不能

保持现有动作与布局；B1–B4位置审核不能代替所有原生组的完整艺术验收。
不改字幕原文、语音、音乐、音效事件或源/输出时间映射。手机按钮和文案区
因界面而变，24%/16%是编辑预设，需对照本期发布界面审核，不是平台认证。

## Coarse fixed face position / 粗略固定脸部位置

图片只检测一次，单人口播视频最多抽五帧，取最大人脸位置的中位数作为
整段固定参考。Windows、macOS、Linux共用本地OpenCV和FFmpeg入口；
XML通过Python读取后在内存加载，避免依赖安装目录中的中文路径交给
OpenCV文件加载器。某一帧失败仍保留其他可用样本，准备报告列出失败阶段。
本节说明跨平台实现，Windows实机结果以包外对应ZIP身份的测试回执为准。
正常doctor还会实际读取并加载XML模型，不能只凭import cv2判断环境可用。
626已有缓存中的模型损坏时保留旧缓存，在新的--cache位置运行正常setup；
继续使用精确依赖锁，不覆盖已有缓存或全局Python。

不做身份识别或实时追踪，不改人物框、圆形/矩形变形或字幕坐标。
用户已有face或有效tracking仍优先；没有可用脸部样本时明确报告undetected，
仅普通居中cover、不额外放大，预览时需要的话给一个粗略人工face提示。
